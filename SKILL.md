# Shield Swap

This is the top-level Shield Swap onboarding guide. When invoked without a concrete task—including `/shield-swap`, `$shield-swap`, or a fresh session started with `skills use`—open the [intro screen](context/getting-started.md) immediately. Invoking the skill is enough: do not wait for a second request or ask what the user needs before showing the guide. Introductory prompts such as “How do I trade with Shield Swap?”, “Get started”, or “Show the menu” open the same guide. Preserve the **SHIELD SWAP** heading, **Private asset trading**, and **YOUR SETUP** box with **Tools**, **Aleo account**, and **Funding**. Below it, show the exact **GET STARTED**, **STRATEGIES**, **INTEGRATIONS [Coming Soon]**, and **CHECK YOUR SETUP** menu from the intro screen. Keep all ten entries and their numbering. Show it again when asked, even after setup. Existing accounts change status values; they never remove the heading or menu.

The guide covers the shared account and funding steps, then routes to the chosen journey using the user’s existing or selected tools. It works with SDK, CLI, and MCP paths; an MCP connection is not required to display it.

When setup is selected or the chosen journey needs an account, load [basic Shield Swap setup](skills/aleo-account-setup/SKILL.md). It handles account creation or import, storage, public balances on both networks, the trading language or existing project, API sign-in, scanner registration, and private balances. Stay in its bundled guidance through the next-step menu; do not jump from account creation to a combined CLI setup/funding command. Keep choices already made. When a funding option is selected, load [fund an Aleo account](skills/aleo-funding/SKILL.md) and pass the verified address, account, project, programming language, execution interface, network, and selected option. Keep that language through source-wallet creation and bridging. It also handles direct requests to fund an account or build funding scripts. For a general funding request, show only its two opening choices: funding guidance or building bridging into an application. Present the remaining steps for the selected path; skip the opening question when the request or setup handoff already selects a path. Preserve that choice: script setup can finish without a transfer and does not mark the account funded. Both skills work independently. Resume a trading journey only after its next action is selected; basic setup itself does not fund or trade.

Use the template in the intro guide. Run [setup inspection](context/shield-swap-setup/inspect-setup.md) against the working project before rendering the opening screen. Keep the banner and setup box in fenced text blocks. Below the box, show **ACCOUNTS** with discovered Aleo, EVM, and Solana accounts and their access status, then **TOOLS** with installed versions and locations, including current agent connections. Render the menu outside code fences with bold option titles and regular descriptions. Keep network choices, journals, and protocol explanations out of the opening screen. Old notes about funding mean **Not checked** until current holdings are read.

For code that adds trading to an application or bot, load [trading integration](skills/trading-integration/SKILL.md). For an arbitrage strategy, load [arbitrage](skills/arbitrage/SKILL.md), which uses that shared execution workflow. Pass the existing project, language, accounts, networks, and authorized limits. A specific integration or strategy request goes directly to its skill without another journey menu. Keep one-off trade execution in the operational swap guide.

Main-menu selections route directly: **1** to account setup, **2** to funding, **3** to [market exploration](context/shield-swap-setup/discover-pools-and-get-quotes.md#explore-markets-from-the-main-menu), **4** to trading integration, and **5** to arbitrage. **6–8** describe coming-soon integrations and have no executable route. **9** runs **Check existing accounts**; **10** runs **Check existing setup**, using the [inspection commands](context/shield-swap-setup/inspect-setup.md#explicit-check-commands). Also recognize `check accounts` and `check setup` directly, including as arguments to this skill. These are inspection requests: run the requested check and show its results without opening account creation, installation, authentication, or the full onboarding menu. Preserve the current project and selected journey. Use the [menu routing table](context/getting-started.md#canonical-journeys), and interpret numeric replies within the most recently displayed menu rather than applying root-menu numbers inside a child skill.

For a concrete task already supplied, retain the heading and status panel and continue that task without making the user select a menu option again. Explicit inspection commands return their targeted report without repeating the banner. After the introduction, read [AGENTS.md](AGENTS.md) and the relevant [tool-use guide](tools/SKILL.md) to carry out the chosen journey. A broad introductory question is not a selected trade or spending authorization.

This file is the installation entrypoint for the whole repository. Keep journey instructions in `AGENTS.md` and the supporting context files. Installing context does not configure tools, create an account, or authorize transactions.
