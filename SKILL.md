# Shield Swap

This is the top-level Shield Swap onboarding guide. When invoked without a concrete task—including `/shield-swap`, `$shield-swap`, or a fresh session started with `skills use`—open the [intro screen](context/getting-started.md) immediately. Invoking the skill is enough: do not wait for a second request or ask what the user needs before showing the guide. Introductory prompts such as “How do I trade with Shield Swap?”, “Get started”, or “Show the menu” open the same guide. Preserve the **SHIELD SWAP** heading, **Private asset trading**, and **YOUR SETUP** box with **Tools**, **Aleo account**, and **Funding**. Below it, show the exact **GET STARTED**, **CHECK SETUP**, **STRATEGIES**, and **INTEGRATIONS [Coming Soon]** menu from the intro screen. Keep all ten entries and their numbering. Show it again when asked, even after setup. Existing accounts change status values; they never remove the heading or menu.

The guide covers the shared account and funding steps, then routes to the chosen journey using the user’s existing or selected tools. It works with SDK, CLI, and MCP paths; an MCP connection is not required to display it.

Before treating missing account commands or imports as an SDK gap, [check npm/PyPI and upgrade outdated tools](skills/aleo-account-setup/references/dependencies.md#check-releases-before-repairing-an-installation) in the selected environment, then retry. Veil/CLI 0.17.0 or higher and Python 0.9.0 or higher include shared account support; use the latest stable release instead of building locally. Apply upgrades during the requested check or task, not merely to show the welcome. Explicitly read-only requests report available updates without applying them.

When setup is selected or the chosen journey needs an account, load [basic Shield Swap setup](skills/aleo-account-setup/SKILL.md). It handles account creation or import, storage, public balances on both networks, the trading language or existing project, API sign-in, scanner registration, and private balances. Stay in its bundled guidance through the next-step menu; do not jump from account creation to a combined CLI setup/funding command. Keep choices already made. When a funding option is selected, load [fund an Aleo account](skills/aleo-funding/SKILL.md) and pass the verified address, account, project, programming language, execution interface, network, and selected option. Keep that language through source-wallet creation and bridging. It also handles direct requests to fund an account or build funding scripts. For a general funding request, show only its two opening choices: funding guidance or building bridging into an application. Present the remaining steps for the selected path; skip the opening question when the request or setup handoff already selects a path. Preserve that choice: script setup can finish without a transfer and does not mark the account funded. Both skills work independently. Resume a trading journey only after its next action is selected; basic setup itself does not fund or trade.

Use the template in the intro guide. Run [setup inspection](context/shield-swap-setup/inspect-setup.md) against the working project before rendering the opening screen. Keep the banner and setup box in fenced text blocks. Go directly from the box to **GET STARTED**. Follow its four options with a separate **CHECK SETUP** section containing **Check existing accounts** and **Check existing setup**. Keep account names, addresses, storage details, tool versions, and install paths in the explicit check reports; do not print those listings automatically. Render the menu outside code fences with bold option titles and regular descriptions. Keep network choices, journals, and protocol explanations out of the opening screen. Old notes about funding mean **Not checked** until current holdings are read.

For code that adds trading to an application or bot, load [trading integration](skills/trading-integration/SKILL.md). For an arbitrage strategy, load [arbitrage](skills/arbitrage/SKILL.md), which uses that shared execution workflow. Pass the existing project, language, accounts, networks, and authorized limits. A specific integration or strategy request goes directly to its skill without another journey menu. Keep one-off trade execution in the operational swap guide.

Main-menu selections route directly: **1** opens account setup, **2** funding, **3** [market exploration](context/shield-swap-setup/discover-pools-and-get-quotes.md#explore-markets-from-the-main-menu), and **4** trading integration. Under **CHECK SETUP**, **5** runs **Check existing accounts** and **6** runs **Check existing setup**, using the [inspection commands](context/shield-swap-setup/inspect-setup.md#explicit-check-commands). **7** opens arbitrage. **8–10** describe coming-soon integrations and have no executable route. Also recognize `check accounts` and `check setup` directly, including as arguments to this skill. Run the requested check and show its results without creating accounts, installing missing tools, authenticating, or repeating the full onboarding menu. Outdated existing tools follow the upgrade guidance above. Preserve the current project and selected journey. Use the [menu routing table](context/getting-started.md#canonical-journeys), and interpret numeric replies within the most recently displayed menu rather than applying root-menu numbers inside a child skill.

For a concrete task already supplied, retain the heading and status panel and continue that task without making the user select a menu option again. Explicit inspection commands return their targeted report without repeating the banner. After the introduction, read [AGENTS.md](AGENTS.md) and the relevant [tool-use guide](tools/SKILL.md) to carry out the chosen journey. A broad introductory question is not a selected trade or spending authorization.

This file is the installation entrypoint for the whole repository. Keep journey instructions in `AGENTS.md` and the supporting context files. Installing context does not configure tools, create an account, or authorize transactions.
